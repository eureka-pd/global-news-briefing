### 5. Rust 1.98.0: algebraic floats and buffered integer formatting

- **Source/time:** GeekNews curation 09:07:54 KST on 2026-08-22; Rust blog dated 2026-08-20 — [GeekNews](https://news.hada.io/topic?id=32749) · [Rust blog](https://blog.rust-lang.org/2026/08/20/Rust-1.98.0/)
- **Source facts:** GeekNews said stable Rust 1.98.0 adds algebraic floating-point methods, buffer-based integer formatting and a documented guarantee for `ManuallyDrop<Box<_>>`. `algebraic_*` on `f32` and `f64` may reorder operations and enable wider loop vectorization; results can be non-deterministic with the optimizer’s choice and never cause undefined behavior. Integer `format_into` writes a decimal `&str` into a `NumBuffer` and performs similarly to `itoa` on the itoa-benchmark. Undefined behavior when moving a dropped `ManuallyDrop<Box<_>>`, removed in 1.96.0, is now guaranteed not to be UB going forward. The official blog says install with `rustup update stable`.
- **Analysis:** The official tag is 20 August, before this window. The in-window event is GeekNews curation. `algebraic_*` is an opt-in fast-math-style API, not a change to default float semantics. Parity with `itoa` is a benchmark, not a guarantee on every target.
