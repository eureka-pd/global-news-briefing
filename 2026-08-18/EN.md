### 2. GitHub reports a multi-hour outage on GitHub.com

- **Source/time:** GitHub Status from 13:40 UTC on Aug. 17 (22:40 KST); GeekNews curation at 23:31:35 KST — [GitHub Status](https://www.githubstatus.com) · [GeekNews](https://news.hada.io/topic?id=32585)
- **Source facts:** GitHub Status said it began investigating impacted performance at 13:40 UTC. At 13:45 UTC it reported about a 20% error rate across experiences including pull requests and issues. A 19:01 UTC note that API requests were operating normally falls one minute after this window. GeekNews also recorded later user reports of pull-request access problems.
- **Analysis:** Status-page recovery notes are operator statements. Residual impact after mitigations means the incident should not be treated as fully closed inside the window.

### 3. DuckDB publishes a preview of v2.0 “Cyanoptera”

- **Source/time:** DuckDB blog dated Aug. 17; GeekNews curation at 02:34:53 KST on Aug. 18 — [DuckDB](https://duckdb.org/2026/08/17/duckdb-20-highlights.html) · [GeekNews](https://news.hada.io/topic?id=32589)
- **Source facts:** Mark Raasveldt and Hannes Mühleisen wrote that DuckDB v2.0, code-named Cyanoptera, is due this fall after more than 10,000 commits since v1.5 in March. Headline items include a stable Quack protocol and `CONNECT` so a DuckDB process can serve databases over the network; `VARIANT` execution from storage; SQL triggers; asynchronous I/O; a new default storage format; a PEG SQL parser; native time zones without ICU; and a broader stable C API. A recursive-CTE microbenchmark in the post fell from 4.90 seconds in v1.5.4 to 0.12 seconds in the preview, about 40 times faster. The authors say details may still change and that breaking changes include the new storage format and completed lambda-syntax transition.
- **Analysis:** This is a preview, not a general-availability release. Microbenchmarks are the authors’ own measurements.
